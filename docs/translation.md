# 翻译（BYOK）

火羽同传使用你自备的 **OpenAI 兼容接口（BYOK）** 进行实时翻译：服务地址、模型 ID 与 API Key 均由你自己提供，费用由对应服务商按你的实际 Token 用量收取。

> 翻译请求仅发送本地语音识别转写出的**纯文本**与提示词，不发送任何音频数据。

---

## 配置入口与服务预设

入口为「设置 → 翻译 API」。服务地址、模型 ID、API Key、User-Agent 与自定义请求头在同一表单编辑。

| 预设 | 服务基础地址 | 初始模型 ID |
|---|---|---|
| DeepSeek 官方 | `https://api.deepseek.com/v1` | `deepseek-flash` |
| 硅基流动（SF） | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V4-Flash` |
| OpenRouter | `https://openrouter.ai/api/v1` | 留空，必须填写账户可用的完整模型 ID |
| 自定义 / 手动填写 | 保留当前表单 | 保留当前表单 |

预设仅填入草稿，不自动保存、不测试连接、不请求模型列表；所有字段都可修改。跨规范化聊天端点切换预设时，草稿清空旧密钥、自定义请求头和 User-Agent，避免带入其他服务；在同一端点切换预设保留这些字段。「自定义 / 手动填写」不清空表单。保存前，已持久化的配置仍保持原值。

- 「保存翻译配置」校验并保存整套配置，本身不发起翻译请求。
- 「测试连接」先保存当前配置，再探测接口与关闭思考参数，最多 6 次请求，可能产生费用；同传运行或启动期间不能测试。
- 有效地址不代表账户有余额、模型权限或服务兼容性，需使用自己的账户测试。本轮未验证用户付费 API。

预设地址与模型命名核查日期：**2026-10-15**。官方来源为 [DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)、[DeepSeek 接入文档](https://api-docs.deepseek.com/guides/codex)、[硅基流动聊天接口](https://docs.siliconflow.cn/cn/api-reference/chat-completions/chat-completions)、[OpenRouter Quickstart](https://openrouter.ai/docs/quickstart)。服务商可随时更改可用模型、命名、权限与价格；预设是可编辑的填写起点，不承诺价格、性能或可用性。

## 对模型的要求

- **优先选择可关闭思考（深度思考 / Reasoning）的模型**：实时字幕需要逐句低延迟返回，开启思考会让每句话多等很久。首次连接某个模型时，App 会自动探测关闭思考所需的参数并缓存（见下文）。
- **尽量选择响应快的模型**：正式翻译采用流式请求（`stream: true`），发出后 **5 秒内**未收到首字即判为失败，单次请求总时限为 **8 秒**（断网或超时显示「翻译失败」，不自动重试）。模型响应越快，字幕越跟得上说话人。

## 协议与「关闭思考」自动探测

### 接口协议与安全策略

- **请求路径**：调用 OpenAI 兼容的聊天完成接口；支持填写基础地址、带 `/v1` 的地址或完整 `/chat/completions` 地址，界面显示规范化后的实际请求地址。OpenRouter 的 `/api/v1` 前缀会保留。
- **鉴权头**：携带 `Authorization: Bearer {key}`；当 API Key 留空时不发送 `Authorization` 头（方便接入无需鉴权的本地或公共服务）。
- **安全约束**：仅接受 `https://` 地址，不允许包含用户名、`?` 查询参数或 `#` 锚点；请求**不跟随 HTTP 重定向**，防止 API Key 被重定向泄露到第三方域名。
- **凭据存储与日志边界**：
  - 当前 Android 客户端使用 **Android Keystore** 加密保存 API Key；桌面凭据机制仅属历史实现。
  - 服务端返回的原始流式报文、思考内容、错误响应正文（可能回显 Key）一律不写入使用记录；仅记录剥离思考内容并抹除 Key 后的最终译文、HTTP 状态码、耗时与 `usage`。

### 自动探测关闭思考参数

各家服务商关闭思考的字段名称并不统一。首次使用某个「服务地址 + 模型 ID」组合时（点击「测试连接」或首次开始字幕），App 会用一句固定的日语依次尝试以下 6 种参数（每次最多等待 8 秒，均计为一次正常请求）：

| 探测顺序 | 请求体附加参数 | 常见适用服务 / 模型 |
|---|---|---|
| 1 | `thinking: {"type": "disabled"}` | DeepSeek、智谱 GLM、豆包等 |
| 2 | `chat_template_kwargs: {"enable_thinking": false, "thinking": false}` | vLLM / SGLang 部署的 Qwen3、DeepSeek 等 |
| 3 | `enable_thinking: false` | SiliconFlow、阿里云百炼（通义千问）等 |
| 4 | `reasoning: {"enabled": false}` | OpenRouter |
| 5 | `reasoning_effort: "none"` | OpenAI 推理模型、Gemini 的 OpenAI 兼容接口 |
| 6 | 不加额外参数 | 本身不带思考模式的常规对话模型 |

- **命中与缓存**：第一种**正常返回译文且未检测到思考内容**的参数会被记录下来，后续对该「地址 + 模型」的所有请求自动沿用（注：这代表该次响应未观测到思考输出，部分服务端也可能隐藏思考过程）。
- **思考内容判定**：响应中包含 `reasoning_content` / `reasoning` 字段、正文出现 `<think>`，或 `usage.completion_tokens_details.reasoning_tokens > 0`，即视为仍开启了思考。
- **异常与回退处理**：
  - 参数不被服务端接受（如 HTTP 400）时自动尝试下一种。
  - 遇到 Key 错误（401 / 403）、地址或模型不存在（404）、限流（429）或网络不通时立即中止探测并报错。
  - 遇到超时或 5xx 等不确定结果时不缓存结论，下次重新探测。
  - 若 6 种方式均检测到思考，会提示「关不掉思考，可能很慢」，但仍允许使用（思考内容不会显示为字幕）。

## 自定义 User-Agent 与请求头

在「设置 → 翻译 API」中直接填写，无需展开旧版 LLM API 弹窗。最多 **20 个自定义请求头**，作用于实时翻译、测试连接与生成术语，不影响 Jev。

- User-Agent 留空使用 `HinomeSub/{版本号}`，如需特殊标识请按服务方文档填写。
- 请求头逐行填写名称和值；名称必须是合法 HTTP 名称，值不得含换行、中文等非法字符。`Authorization`、`Content-Type`、`Host`、`Content-Length`、`User-Agent` 等保留头不能覆盖。
- 请求头值与 API Key 一起加密保存，使用记录仅包含请求头名称。点击「保存翻译配置」才会持久化；运行中保存后，后续句子按整套配置切换。

第三方公共端点可能要求特殊头、限制模型或停止服务；本文不将旧版公共免费接口作为当前可用服务承诺。

## 提示词结构与前缀缓存（Prefix Cache）

每次翻译请求的消息结构专为支持**服务端前缀缓存（Prefix Caching）**而排布，将整场会话不变的内容全部收敛在最前端：

```text
┌────────────────────────────────────────────────────────────────┐
│ system 消息（同一套设置下每句完全相同）                          │
│   • 翻译规则、源语言与目标语言要求                             │
│   • 当前场景的背景说明                                         │
│   • 整份场景术语表（仅当目标语言与术语表目标语言一致时附带）    │
├────────────────────────────────────────────────────────────────┤
│ user 消息（随每句动态变化）                                     │
│   • 【前文】最近 N 句已定稿的原文（仅用于理解指代与省略）       │
│   • 【当前句】本次待翻译的识别文本                             │
│   • 【注意】Jev 检出明显错译并触发重译时附带的修正说明          │
└────────────────────────────────────────────────────────────────┘
```

- **生成参数**：`temperature: 0`；单句最大输出上限：预设中文为 **160 Token**，其他语言为 **256 Token**。原声语言选「自动识别」时，提示词中写为「外语」由模型自行判断。
- **跨句前缀复用**：服务端前缀缓存只复用输入开头完全一致的连续 Token。把固定指令、背景说明与整份术语表全部放在 `system` 消息中，可以让不同句子之间最大化复用 `system` 前缀（各服务商是否支持缓存、最小触发阈值及缓存粒度以服务商文档为准；使用记录的 `mt` 事件会记录服务端回报的 `cached_tokens`）。
- **单句内本地复用**：同一句话在「草稿 → 定稿 → 重译」阶段若拼装出的完整提示词与上一次完全相同，客户端会直接复用上一次译文，不再发起网络请求。

## 结合上文（Context Window）

「设置 → 高级设置」中的「结合上文翻译」默认开启，默认参考最近 **2 句**（可调为 **1–5 句**或关闭；运行中修改从下一句起生效）：

- **仅收录非空定稿**：上文窗口只取最近几句非空定稿的**原文**，动态变化的草稿不会进入上文。
- **段内上下文锁定**：某一段话的上文窗口在它前一句定稿翻译完成时即固定下来，确保该段从草稿到定稿使用相同的提示词上下文。
- **延迟权衡**：参考句数越多，每次请求输入的文本越长，可根据模型响应速度酌情增减。

## 内容场景与术语表

进入独立导航「场景术语」可编辑场景或创建自定义场景；在「同传」页选择当前场景。每个场景包含：

- **场景名称**（最多 20 字）
- **背景说明**（最多 1,000 字）
- **术语表**（最多 200 条；每条左侧填原文、右侧填译文，各最多 40 字，中间的 `→` 由 App 自动拼接）

### 内置场景

| 场景名称 | 背景说明 | 术语表 |
|---|---|---|
| **通用** | 无 | 无 |
| **B站 VTuber 直播** | B 站直播闲聊、念弹幕和 SC、原文来自语音识别（源语言非日语时自动将“日本虚拟主播”调整为“虚拟主播”） | `ビリビリ→B站`、`スパチャ→SC`、`配信→直播` 等 |

- 内置场景支持自行编辑，修改后可点击「恢复默认」并确认还原；自建场景支持「删除场景」并确认（删除当前使用中的场景会自动切回「通用」）。
- **术语表的目标语言匹配（`termsLang`）**：每个场景的术语表都绑定一种「术语译文语言」（内置场景为中文，新建场景时默认为当前字幕语言）。**只有当当前字幕目标语言与术语表语言一致时，才会将术语表放进提示词**；不一致时不会附带；修改字幕语言后应检查术语译文语言是否匹配。

### AI 辅助生成术语

编辑场景时点击「生成术语」，App 会调用当前配置的翻译接口，根据场景名称与背景说明自动列出该领域常见、易译错的词汇（条数上限可填 1–100，默认 20）：

- **只增不改**：已保存和正在编辑的术语保持原样；生成结果中与现有原文重复的词条会自动跳过，新词条追加在末尾，需点击「保存场景」后才会正式落盘。
- **格式清洗**：单次请求最长等待 1 分钟；自动剥离列表编号与符号，丢弃不含 `→` 或超长的无效行。

## 支持的语言

- **视频原声语言（原文）**：ReazonSpeech 为日语、英语与自动识别；SenseVoice 为中文、英语、日语、韩语与自动识别。SenseVoice 权重也支持粤语，目前语言下拉没有独立粤语项，可使用自动识别；语言选择用于提示词与 Jev，不会将 SenseVoice 解码从 `auto` 改成强制语种。
- **字幕显示语言（译文）**：
  - **预设语言**：中文、英语、日语、韩语。
  - **自定义语言（「使用其他字幕语言」→「自定义字幕语言」→「应用自定义语言」）**：可填写任意语言或方言名称（最多 40 字，如 `法语`、`繁体中文（台湾用语）`、`粤语`），名称会原样写入翻译提示词与 Jev 检查问题中（内部保存为 `targetLang = custom:<名字>`）。
- **日译中专项调优**：仅预设列表中的「中文」启用专门调优过的日译中检查与修正提示及 160 Token 输出上限；通过自定义入口输入的语言（即使填写“中文”）均按通用模板处理（256 Token 输出上限）。

「字幕样式 → 最多显示行数」仅控制显示，不裁剪这里的上下文窗口，也不改变会话记录。
