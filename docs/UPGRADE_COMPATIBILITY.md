# 首版升级兼容

已验证：首个正式版 **v1.8.4（36）→ v2.4.2（47）**。

用户使用正式签名安装包直接覆盖更新，即可保留配置与已下载模型；不需要卸载、清除数据或重新下载模型。

开发预览包使用开发证书；升级正式版应使用正式签名包。

## 验证内容

同一台模拟器上，从首版标签源码构建独立包名的验证包，使用首版实际代码保存配置与加密密钥，再以 `adb install -r` 覆盖安装新版验证包。隔离包的 UID 在覆盖安装前后保持一致。生产 APK 的包名和签名单独与 GitHub 首版发布附件核对，未用验证包替换用户原应用。

88 项保留检查全部通过，包括：

- 字幕大小、透明度、宽高、显示方式、保留模式、位置与基线。
- 语言、上下文、记录开关、首次引导完成标志与自定义主题。
- 翻译配置目录、名称、当前选中项、地址、模型、密钥、User-Agent 与加密请求头。
- 同一平台的不同翻译密钥，以及 OpenRouter 翻译与 Jev 的独立密钥。
- 自定义场景、背景与术语。
- ReazonSpeech、SenseVoice 两款完整模型：8 个文件的长度、SHA-256、修改时间和选中状态；新版直接校验为可用，无需下载。
- 重复初始化后仍保持同一配置与密钥。

另外，54 项设备回归和 536 项单元测试通过。原开发应用覆盖更新后，44 项既有配置与 8 个模型文件再次核对，均未变化。测试没有请求真实供应商、启动录音、清除应用数据或删除用户模型。隔离验证包已停用，复查证据保留在本地忽略目录 `.qa/upgrade-184/`。

## 本次修复

v2.4.1 的旧凭据迁移按平台选择一把默认密钥，导致首版同平台的备用配置、同平台 Jev 服务改用另一账号。

v2.4.2 保留原有平台默认策略；不同旧密钥迁成独立命名凭据，并为原服务保存对应绑定。相同密钥去重；原本空密钥的配置保持空，不借用其他账号。默认、目录、绑定和完成标志同次提交，失败不留下半份迁移。

旧密文字段保留。已经迁移或由用户显式编辑、清空、删除的新版凭据优先，不重复用旧数据覆盖新选择。

回归入口：`LegacyCredentialMigrationDeviceTest`、`PlatformCredentialsDeviceTest`、`MultiPlatformKeysDeviceTest`、`PlatformDefaultCredentialDeviceTest`、`PlatformKeyDeletionDeviceTest`、`PrefsProfilesDeviceTest`。
